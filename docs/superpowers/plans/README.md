# План реализации GovErp

Все четыре этапа описаны и согласованы со спекой и манифестом. Этапы 1–2 выполнены в ветке `codex/foundation`: 344 теста зелёные, сборка без предупреждений. Код домена — источник истины: план 3 переписан под его фактический API, открытые компромиссы собраны в [DEBT.md](../../DEBT.md). Фрагменты кода в планах 3–4 проектные и до выполнения не собирались.

Уточнения из [сверки 22 сентября](2026-09-22-plan-consistency.md) уже внесены в планы; документ сохранён как обоснование решений. Исполнителю задачи достаточно текста её плана.

| Порядок | Документ | Результат этапа |
|---|---|---|
| 1 | [Foundation and Domain](2026-09-21-plan-1-foundation-and-domain.md) | Решение, четыре доменных модуля, shared kernel, инварианты и тесты — **выполнен** |
| 2 | [Validation](2026-09-21-plan-2-validation.md) | Чистый конвейер, версии правил, результаты, маршрут и preview — **выполнен** |
| 3 | [Infrastructure and Application](2026-09-21-plan-3-infrastructure-and-application.md) | SQL Server, tenancy, атомарные сценарии, Docker и интеграционные проверки |
| 4 | [UI, explanations and demo](2026-09-22-plan-4-ui-explanations-and-demo.md) | Логин, Blazor UI, сменные LLM, README и демонстрация |

Планы выполняются последовательно. После каждого этапа — сборка и проверки его результата. Ключи API не нужны для Domain/Validation или для тестов адаптеров на подставных клиентах; реальный LLM smoke-test требует выбранного провайдера и доступной модели.

Готовность: все четыре этапа выполнены, тесты пройдены на SQL Server, Docker запускается повторно без потери данных, сквозной сценарий пройден с разными логинами, подтверждён хотя бы один реальный LLM-вызов либо явно зафиксирована его недоступность. Выпуск приложения во внешнюю сеть не входит в этот план.
